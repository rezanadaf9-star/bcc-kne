# BCC website: Android feature integration

## Changes
- Student lecture player: shared comments, student doubts, threaded replies, staff role labels, own-comment deletion.
- Teacher/admin: Discussions navigation, lecture list, comment counts, awaiting-staff-reply counts, staff replies and moderation.
- Student: Notifications navigation, class-scoped notification feed, read status, mark all read, deep links.
- Original HTML/CSS/JS portal and existing theme preserved; no framework migration.

## Setup
1. Back up your existing website files.
2. Replace `index.html`, `app.js`, and `style.css` with the versions in this package. Keep `config.js`, assets and your other files unchanged unless deploying this entire directory.
3. In your existing Supabase project's SQL Editor, run `supabase/APP_FEATURES.sql`, then `supabase/APP_FEATURES_2_REPLIES.sql` from the **Android project** (copies are in this package under `supabase/`). These migrations are necessary for comments, replies and notifications.
4. Use the same Supabase URL and anon key in the website and Android app.
5. Test with a student, an assigned teacher, and an administrator.

## Important notes
- The awaiting-reply metric counts student root comments with no teacher/admin reply; it does not mean every comment is necessarily a question.
- Website notifications display events stored in `app_notifications` (including those generated by the Android app). Automatic notification publishing from every website content-management action is not yet wired.
- This package has passed JavaScript syntax validation, but has not been end-to-end tested against your live Supabase project or deployed.
- The existing backend RLS policies determine actual access and moderation permissions.
