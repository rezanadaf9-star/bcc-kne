# BCC Teacher Portal — deployment steps

The website changes are additive: the student portal and the existing visual theme remain in place. Teacher IDs use `BCC01ZQ` format: `BCC` + a sequential serial number (minimum two digits) + the first letter of the first name + the first letter of the second name. For example, a teacher named Zain Qureshi could receive `BCC01ZQ`; the next teacher would receive serial `02` with their own initials. Passwords are set/generated by the administrator and cannot be changed from the teacher portal UI. Admins can reset passwords.

## 1. Back up first

Export your current Supabase database schema/data and keep a copy of the currently deployed website before applying changes.

## 2. Run the SQL migration

In the existing Supabase project, open **SQL Editor** and run:

`supabase/migrations/20261015000100_teacher_portal.sql`

This migration assumes your existing base schema and academic marks migration are already installed, as in the current BCC project. It adds the active status, teacher class assignments, ID sequence, and class-level RLS rules. Do not run this as a replacement for the existing schema. Then run `supabase/migrations/20261015000200_teacher_id_initials_format.sql` to install the initials-based ID format. The second migration is required even if the first teacher migration was already run.

## 3. Deploy the Edge Function

Deploy the updated `supabase/functions/admin-create-user/index.ts` to the **existing** project under the existing function name `admin-create-user`. It uses the project's existing Supabase environment secrets. Do not place a service-role/secret key in `config.js` or browser JavaScript.

Example using Supabase CLI from the project folder:

```bash
supabase functions deploy admin-create-user
```

If the project is not linked in the CLI yet, link it to the existing Supabase project first. Do not create a new project.

## 4. Publish the website

Publish the updated `index.html`, `app.js`, `style.css`, assets and existing project files to the same hosting location currently used by BCC. Keep the existing `config.js` values unchanged.

## 5. Create teacher accounts

Log in with an administrator account, open **Teachers**, choose **Create teacher**, enter the teacher’s full name (at least two name parts, used to generate the initials), select Class 10 and/or Class 12, and set a password or leave it blank to generate one. Copy the prepared WhatsApp message and send it privately. The next teacher gets the next BCCA ID from the database sequence.

## 6. Test before using with staff

- Admin can create a teacher and copy the credential message.
- A teacher can log in through the Teacher tab with a `BCC01ZQ`-style ID.
- Teachers see only their teacher navigation, not teacher-account management.
- Teacher class access is restricted by database policies to assigned classes.
- Admin can deactivate/reactivate teachers and reset their passwords.
- Existing student login, quiz flows, marks, content, photos and leaderboard still work.

## Important behavior

- Teacher account creation and management are admin-only, enforced by the Edge Function.
- Teacher accounts are created as active by default.
- Deactivated accounts are blocked at login, and teacher class-access helper checks also require active status.
- Supabase Auth stores password verifiers; this app does not store teacher passwords in the public `profiles` table. The admin must retain/send the initial password at creation/reset time because it cannot be retrieved later.
- The teacher dashboard and class assignment UX are designed for the current Class 10 and Class 12 structure in this BCC project.
